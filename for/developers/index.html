MODULE SDK

Ship a module in a week

The SDK gives you identity, vault access, on-device LLM, credential gating, and distribution. You focus on your domain logic.

01

Clone the template

Start from cr-driving as your reference. It implements every SDK interface with real logic you can study.

02

Define your manifest

Set your module ID, required credentials, capabilities, routes, and icon. The manifest tells the shell what your module needs and provides.

03

Implement install()

The shell calls install(ctx) with a context object. You get credential access, storage, LLM, biometric auth, navigation, and inbox push.

04

Build your views

Vue 3 components, lazy-loaded via your manifest routes. The shell handles auth, navigation chrome, and credential gating.

05

Add onboarding + exams

Optional: return an OnboardingFlow with contextual LLM prompts. Add proctored exams with mastery tracking and VC issuance on completion.

06

Submit to the registry

Open a PR to the module registry. Community testers validate. Once merged, your module is available to every Attestto user.

The Module Interface

interface AttesttoModule {
  manifest: ModuleManifest
  install: (ctx: ModuleContext) => Promise<void> | void
  uninstall?: () => void
  getInboxItems?: () => Promise<InboxItem[]>
  getHomeWidget?: () => Component | null
  getOnboarding?: () => OnboardingFlow | null
}

interface ModuleManifest {
  id: string                      // unique, e.g. "cr-driving"
  name: string                    // display name
  country: string                 // ISO 3166-1 alpha-2, or "universal"
  version: string                 // semver
  description: string             // short description
  icon: string                    // Material Icons name
  requiredCredentials: string[]   // VCs that must be in vault
  capabilities: string[]          // e.g. ['exam-practice', 'issue:MyVC']
  routes: ModuleRoute[]           // routes this module contributes
}

interface ModuleContext {
  getCredentials: (types: string[]) => Promise<VerifiableCredential[]>
  storeCredential: (vc: VerifiableCredential) => Promise<void>
  pushInboxItem: (item: InboxItem) => void
  requestBiometric: (reason: string) => Promise<boolean>
  navigate: (path: string) => void
  storage: ModuleStorage          // key-value, namespaced to module ID
  llm: LlmHandle                 // on-device Gemma 2B via WebGPU
}

What the Platform Gives You

Identity

User's DID, credential vault, WebAuthn biometric auth. You never manage keys.

Credentials

Read from vault, write to vault, gate access by credential type. W3C Verifiable Credentials.

On-device LLM

Gemma 2B runs locally via WebGPU. Contextual help, Q&A, document analysis. No data leaves the device.

Storage

Namespaced key-value store. Your data is isolated from other modules. Persists across sessions.

Inbox

Push notifications, action items, and warnings to the user's home screen. Priority-sorted.

Distribution

Your module is available to every Attestto user. PWA on mobile, Station on desktop. No app store needed.

ECONOMICS

You earn 60% of every transaction. Forever.

No upfront cost. No subscription. Build a module, submit it, and earn a majority share of every transaction fee your module generates.

60% You (Builder) Your revenue share
25% Attestto Platform + infrastructure
10% Testers Quality assurance
5% Open Community fund

Example: NotarialOS

8,000 notaries, ~20 filings/month, $2 per filing = $320K/month gross. Your 60% = $192K/month. That's the addressable market for a single Costa Rica module.

Institutional Sponsors

When an institution sponsors your module (e.g., a bank sponsors FinancialInclusion), the split adjusts: 50% Attestto / 35% sponsor / 10% testers / 5% open. You negotiate directly with the sponsor.
